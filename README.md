# Mectov OS

[![CI Boot Test](https://github.com/MAliffadlan/Mectov_OS/actions/workflows/build-boot-test.yml/badge.svg)](https://github.com/MAliffadlan/Mectov_OS/actions/workflows/build-boot-test.yml)

A monolithic x86 kernel written from scratch in C and Assembly — no external libraries, no libc, no POSIX. Every byte runs directly on hardware: GRUB Multiboot boot, protected mode with paging, a graphical desktop with a floating-window manager, a real Unix process model, and an SMP scheduler that runs user tasks on all four CPU cores.

## Overview

Mectov OS is a from-scratch i386 operating system with:

- **Ring 0 / Ring 3 isolation** — user applications run in separate address spaces with COW fork, demand-paged `mmap()`, and per-process page directories — on **PAE 3-level paging with NX (W^X)** since v38.49: user heap/stack/mmap pages are non-executable, and an instruction-fetch fault on data kills the task with SIGSEGV (`nxtest` proves it in CI).
- **True SMP** — per-CPU runqueues, work-stealing migration, and a LAPIC timer per core; all four QEMU cores execute tasks (verified live by SysInfo's per-core load bars).
- **A Unix process model** — `fork` / `exec` / `waitpid`, POSIX signals (`sigaction`, `sa_mask`, `SA_RESTART`), process groups, sessions and a controlling terminal with SIGTTIN/SIGTTOU, plus System V shared memory, pipes, and fds.
- **Ownership, permissions & real threads (v38.23–v38.24, v38.27)** — every file carries a POSIX uid/gid + 9-bit mode enforced at the syscall layer (`chmod`/`chown`/`ls -l`, root bypass, ext2-persisted); every task has a private `%gs` TLS descriptor with `clone()` + a pthread-style runtime, so thread-local variables are genuinely per-thread; futex-based `mct_mutex_t`/`mct_cond_t` (pthread-style) are proven on 4 cores by `conddemo`; and **POSIX resource limits (v38.28)** — `RLIMIT_NPROC`/`RLIMIT_AS`/`RLIMIT_NOFILE` per task with soft/hard values, POSIX `getrlimit`/`setrlimit` privilege rules, and enforcement at fork/clone/thread-create, fd allocation, and heap/mmap growth, so a fork bomb or an fd/memory leak can no longer take the whole system down.
- **A real shell (msh)** — env vars with `$VAR` expansion, aliases, tab completion, scripts, job control, and a growing POSIX toolkit (`uname`, `whoami`, `hostname`, `env`, `seq`, `head`, `grep`, `cp`, `mv`, `df`, ...).
- **A graphical desktop** — double-buffered window manager (resize, Aero snap, rounded corners), taskbar with system tray and clickable window buttons (minimize/restore, hover-highlighted, v38.39), a Start menu with search-as-you-type filtering (v38.40), draggable persistent icons with gradient tiles, soft shadows and label chips (v38.46), and a graphical login screen.
- **Eager FPU/SSE context switching (v38.41)** — every task carries a 512-byte `fxsave` image the scheduler swaps on every context switch, so DOOM's x87 and any Ring 3 float/SSE code can be preempted against each other safely (proven by `fputest`: two forked processes accumulating in live x87/SSE registers).
- **Runtime mounts & POSIX sockets (v38.42–v38.43)** — a real mount table with `mount`/`umount` (syscalls + shell builtins, root-only), and an fd-integrated socket API (`socket`/`bind`/`listen`/`accept`/`connect`/`sendto`/`recvfrom`) where accept spawns per-connection slots POSIX-style and read/write/poll/select work on socket fds uniformly.
- **Real ACPI poweroff (v38.45)** — the FADT is parsed for the PM1a/b control blocks and the DSDT `\_S5` package, so `shutdown` writes the firmware's own sleeping type + SLP_EN; QEMU exits by itself (`poweroff_test` asserts it).
- **On-disk persistence** — an ATA-backed VFS, a fully writable ext2 partition (verified with host `fsck.ext2`), a FAT32 volume at `/fat32` (drive 3, LFN read/write), an **AHCI/SATA driver (v38.50)** that registers SATA disks as drives 4+ and an **xHCI/USB 3.0 driver (v38.56)** that registers SuperSpeed sticks as drives 8+ on the same sector API — ext2/FAT32 and runtime `mount()` work on SATA/USB volumes unchanged — and a **virtio-blk driver (v38.78)** for KVM speed (transitional legacy PCI, poll-only) that registers disks as drives 12+ on that same API.
- **Networking** — RTL8139 driver with IRQ-driven RX, 16-connection TCP with a listener/backlog accept model, UDP, ARP/ICMP/DNS, and a browser that reaches the real internet through a host gateway proxy.
- **Audio** — Sound Blaster 16 driver with WAV playback and PC-speaker tones.
- **Developer tooling** — in-kernel GDB stub (attach over TCP, breakpoints, single-step), ELF32 + custom `.mct` loaders, and a shared-library runtime that keeps app binaries under 2 KB.

## Highlights

**FPU context switching, runtime mounts, POSIX sockets & ACPI S5 (v38.41–v38.45)**
- **Eager fxsave/fxrstor (v38.41)**: `task_t` grew a 16-byte-aligned 512-byte fxsave image; `schedule()` swaps it with IF=0 under `task_lock` (SMP-safe, no per-CPU owner tracking). Fresh tasks are seeded from a canonical `fninit` template, `fork()` inherits the parent's live state, `exec()` resets it (POSIX). CR4.OSFXSR/OSXMMEXCPT are enabled per-CPU (BSP + every AP); #NM is a logged safety net and #XM delivers `SIGFPE` to Ring 3. `apps/fputest.c` + `scripts/fputest.py` prove two forked processes accumulating in live x87-stack and SSE registers across preemption both stay exact — the exact scenario the old "single FPU owner" design could not survive.
- **Runtime mount table (v38.42)**: `SYS_MOUNT`/`SYS_UMOUNT` (root-only) + `mount`/`umount` shell builtins over a mount-point table; the boot `/ext2` and `/fat32` mounts are its first two entries, `umount` drops the subtree and restores a plain directory, `mount` re-inits the backend and re-populates from the real disk. `scripts/mount_test.py` does a full umount → refuse-non-mount → remount → fat32demo-PASSES roundtrip.
- **POSIX socket API (v38.43)**: `socket`/`bind`/`listen`/`accept`/`connect`/`sendto`/`recvfrom` (syscalls 108–114) return ordinary fds — `read`/`write`/`close`/`poll`/`select` are socket-aware. The listener model is POSIX-shaped: a LISTEN slot never mutates; each inbound SYN spawns a fresh child slot (free slots = backlog) and `accept()` hands completed children out one by one. `socktest.py` verifies a guest→host client echo (10.0.2.2) AND a host→guest server accept (hostfwd) end to end with PING/PONG.
- **Capacity bumps (v38.44)**: TCP connections 8→16, global fd table 128→256 (socket-heavy servers), windows 16→32. `MAX_TASKS` stays 64 (GDT TLS coupling) and `MAX_NODES` 256 (on-disk format), both documented in code.
- **ACPI S5 (v38.45)**: `acpi_init` now records the FADT in addition to the MADT (both XSDT and RSDT paths scan every entry), parses the DSDT `\_S5` package for the real SLP_TYP values, and `shutdown` writes PM1a/PM1b with SLP_EN before falling back to the legacy hardcoded ports. `poweroff_test.py` asserts the QEMU process exits by itself.

**Scheduling & SMP (v36.7–v36.8)**
- Per-CPU runqueues: each core picks with priority + aging, steals work from idle peers (migration), and parks in a pinned Ring 0 idle task.
- LAPIC timer per Application Processor, PIT-calibrated once on the BSP (concurrent calibration corrupted the shared PIT and caused timer storms).
- Every runqueue mutation under one `task_lock`, cli-first — the timer IRQ can never self-deadlock in `schedule()`.
- Per-CPU load sampling exposed to Ring 3: SysInfo renders four live utilization bars; the serial log prints `[LOAD] c0=.. c1=..` every 3 s.
- `smpstress` forks 8 children (CPU burn + sleep + pipes + self-signals) in two parallel waves across all four cores — all 16 exit and are reaped.

**Process model & signals (v36.1–v36.6, v38.5–v38.7)**
- COW `fork()` with deterministic syscall-frame copying (the KVM fork-GPF fix), in-place `exec()` via live-frame patching, blocking `waitpid()` with WNOHANG.
- POSIX signals with `SIGACTION`/`SIGPROCMASK`, handler sigframes on the user stack, `SA_RESTART` re-parking interrupted sleeps — and unresolvable Ring 3 faults deliver `SIGSEGV` to user handlers instead of killing the task.
- Process groups + sessions + controlling terminal: `setpgid`, `setsid`, `tcsetpgrp`; background readers get stopped by SIGTTIN; Ctrl+C/Ctrl+Z target the foreground group.
- Real pipelines and redirection: `run A | run B`, `run A > file`, `run A < file` through dup2 + a per-task fd table.
- Job control: Ctrl+Z stops, `jobs` lists, `bg` resumes, `fg` waits, `kill %1` terminates.
- Demand paging for heap and stack: a shared lazy zero page + COW backs untouched pages, and an unmapped guard page catches stack overflow cleanly.

**Shell & toolkit (v36.9, v37.x)**
- POSIX-style builtins across three toolkit rounds: `uname`, `whoami`, `hostname`, `env`, `seq`, `head`, `wc`, `type`, `cat -n`, `yes`, `printf`, `sort`, `uniq`, `tee`, `find` — all pipe-aware.
- Shell scripting: `for VAR in list`, `while true/false`, `$VAR` expansion, `break`, 4-level nesting; env vars + aliases + tab completion.
- `passwd` stores the login password in `/etc/passwd` as `<salt_hex>:<sha256>` since v38.52 (single source, no hardcoded default, no plaintext on disk); a single `OS_VERSION` constant keeps the help banner, `mfetch`, `uname` and login footer in sync.

**Memory & kernel hardening (v38.3–v38.8)**
- Frame-bitmap physical allocator sized from the multiboot memory map (RAM above 128 MB usable; identity map to 512 MB), per-process address spaces, COW with frame refcounting, demand-paged `mmap()` (`0x40000000..0x80000000`), System V shared memory.
- File-backed `mmap()` (`SYS_MMAP_FILE` + `SYS_MSYNC`): pages fault in from disk on demand, dirty pages write back on msync/munmap, `fork()` shares them MAP_SHARED-style.
- 16 KB kernel stacks with a 4 KB guard page below each; vector 8 is a hardware task gate so an overflow prints `[PANIC] DOUBLE FAULT` instead of triple-faulting into a silent reboot.
- Lock audit: per-structure irqsave spinlocks replaced global `cli()` — syscalls are preemptible and SMP parallelizes; heap gets magic + canary + redzone, clean panic on double-free, OOM returns NULL.
- `dmesg` — a 64 KB in-memory kernel log ring (crash lines included) exposed via `dmesg` and `/proc/dmesg`.

**Filesystems & storage (v37.0, v38.12, v38.15–v38.16, v38.23, v38.25)**
- Persistent VFS with auto-save; a fully writable ext2 partition (host-verified `fsck.ext2` clean); a **FAT32 volume at `/fat32` (drive 3) with long file names (LFN) read AND written**, interoperable with host `mkfs.fat`/mtools both ways.
- **Bus-mastering IDE DMA (v38.26)**: the PIIX3 IDE controller's BMIDE engine moves the data itself through a Physical Region Descriptor table — the CPU programs the PRDT + command and waits, no port I/O in the data path at all. Under KVM a 160 KB uncached read dropped **~42 ms → ~1.3 ms (~31×)**, and ~510× vs the original per-sector PIO (~680 ms); `scripts/bigread_test.py` now asserts DMA was engaged and no transfer failed. (v38.25 added multi-sector PIO batches + `rep insw`/`rep outsw` as the no-DMA fallback.)
- POSIX file positioning: `SYS_LSEEK` (`SEEK_SET/CUR/END`), `SYS_FSTAT`, honored `O_APPEND`; fd reads advance a real offset.
- **Ownership & permissions (v38.23)**: every VFS node carries a POSIX uid/gid + 9-bit mode, enforced at open/read/write/create/delete/exec in the syscall layer — root (uid 0) bypasses, `chmod` needs ownership, `chown` is root-only, and chmod while a descriptor is open takes effect on the *next* read/write. `SYS_CHMOD`/`SYS_CHOWN` (+ shell `chmod`/`chown` builtins and `ls -l`), persisted to ext2 inodes so permissions survive the image. FAT32//proc//dev keep no permission concept.
- Virtual `/proc` generated live from kernel state: `/proc/tasks`, `/proc/meminfo`, `/proc/cpuinfo`, `/proc/uptime`, `/proc/version`, `/proc/dmesg`.

**Network (v35.5, v38.11, v38.43)**
- 16-slot multi-connection TCP with seq/ack, retransmit/timeout sweeps, a full FIN handshake, and a listener/backlog `accept()` model (the listener never becomes the connection — each inbound SYN gets its own slot); UDP bind/send/recv (fd-integrated datagram sockets, single global binding); DNS via the QEMU gateway.
- **DHCP client (RFC 2131)** configures IP/netmask/gateway/DNS at runtime over UDP broadcast, with static fallback (`ipconfig` prints the result); RTL8139 IRQ-driven RX (spinlock-guarded against the SMP TX race).

**GUI & input (v37.x–v38.x)**
- Double-buffered WM: dirty-region tracking, Aero snap, 8-directional resize, traffic-light controls, scroll-wheel events (IntelliMouse), 32-window capacity (v38.44), shared `ps2_drain()` arbitration so keyboard and mouse never steal each other's bytes.
- Instrument-console identity: a Windows-style lock screen → password login, live RTC clock. The whole chrome is **full black** (v38.37) — taskbar with neutral bevels (no warm/orange tint), a plain centered **"START"** label instead of the amber logo square, and **window chrome** (titlebars + borders) pure black with off-white title text and window-control glyphs (no amber hairline around focused windows); amber survives only as selection feedback inside the Start menu/calendar popups.
- **Login gate (v38.30–v38.33)**: full-bleed scaled wallpaper (never cropped), digital clock + full date (day, date, month, year) pinned bottom-left, SPACE-only password entry, and a 4-second idle fallback back to the clock view. The lock screen is deliberately bare — no branding, no hint, no version footer (v38.33). While the password panel is open (v38.31) the wallpaper **blurs** and every caption **disappears**, so the panel is the only thing in focus. Every switch between the two screens **cross-fades** (v38.32): the blur eases in/out, the captions fade, and the panel fades — one lerp pass animates all of it, in both directions.
- **Lock screen feature (v38.34)**: the login gate is no longer only a boot/logout screen — a **Lock** item in the Start menu, the **Ctrl+Alt+L** shortcut, and the `lock` shell builtin all run the gate **without resetting the session**: every window and task stays alive behind the lock (the old text-mode `lock` stub printed "System Locked" and verified nothing; it's now a flag the kernel main loop polls, `pending_lock`). Unlocking with the password restores the desktop via `full_redraw()` — verified pixel-identical, terminal window included. **Idle auto-lock (v38.51)**: `locktimeout <seconds>` arms a countdown that locks the same way once keyboard+mouse have been quiet that long (`0` disables); the countdown restarts on any input and is re-anchored after unlock so the desktop never re-locks immediately.
- **Kernel CSPRNG + hardened passwords (v38.52)**: a ChaCha8 DRBG (`src/sys/entropy.c`) is seeded at boot and fed continuously from the timer IRQ + every keyboard/mouse byte; `/dev/random` and TCP ISNs now draw from it, a new `SYS_GETRANDOM` syscall (117) exposes it to Ring 3, and `passwd` writes a salted SHA-256 hash (`salt:hash`) instead of plaintext — legacy plaintext files still verify until the next change.
- **Ring 3 scanout takeover — the display-server foundation (v38.53)**: `SYS_FB_MAP` (118) maps the VBE linear framebuffer read/write into a Ring 3 task as `PAGE_DEV` PTEs (never COW'd on fork, never refcounted or freed by the frame allocator, not inherited by children), authorized logind-style — uid 0 or the controlling terminal's foreground process group; while the holder lives, **the kernel desktop stops presenting frames entirely** and keystrokes pump to it through the same queue `SYS_GET_KEY` pops (`SYS_FB_RELEASE` (119), exit or exec hands the pixels back and the desktop repaints). The clone/free page-table walkers skip `PAGE_DEV` entries — closing a latent unbounded-refcount OOB on MMIO addresses fork would have hit. `apps/fbmap.mct` animates straight to the scanout, then chases the mouse until any key releases; `scripts/fbmap_test.py` proves both the clean-release roundtrip AND a Ctrl+C kill mid-takeover with the desktop restored.
- Smooth compositing: delta-copy VRAM presentation (~10× less MMIO traffic), truthful FPS HUD, tick-scaled 60 FPS cap — <1 ms/frame on KVM.

**App runtime & tooling (v38.3, v38.13, v38.24, v38.27)**
- `.mct` binary format + standard ELF32 loader + shared-library runtime (app binaries ~2 KB); the first **Rust** Ring 3 app (`apps/rusthello.rs`, `no_std`, same MCT1 format) proves the loader is language-agnostic.
- **Real per-thread TLS + `clone()` (v38.24)**: every task slot owns a private FS/GS GDT descriptor (DPL=3) whose base is the thread's control block, saved/restored with the context-switch frame in all three interrupt stubs — so `%gs:0` is a genuine per-thread pointer that survives preemption, signals, fork and CPU migration. `SYS_CLONE` (child stack + TLS base) creates threads sharing the caller's address space; `SYS_TLS_SET` installs/removes the current thread's TLS; `apps/lib/thread.h` gives apps a tiny pthread-style runtime (`mct_tls_init`/`mct_thread_create`/`mct_thread_join`), and `threaddemo` proves isolation — 4 cloned workers each bump a private counter in their own TCB, every one landing on exactly `ITERS`.
- **Futex mutexes + condition variables (v38.27)**: `apps/lib/sync.h` gives apps pthread-style `mct_mutex_t`/`mct_cond_t` on top of `SYS_FUTEX_WAIT`/`SYS_FUTEX_WAKE` — the mutex fast path is one `lock cmpxchgl`, the slow path parks the thread in the kernel (`TASK_STATE_BLOCKED`, burns no CPU, works across cores); the condvar keeps a sequence counter so a signal racing the sleep is never lost, and the kernel's `futex_wait` re-checks the value under its lock. `apps/conddemo.mct` proves both on 4 cores: 4 threads bump a shared counter to exactly 20,000 under the mutex, then 2 producers + 2 consumers move 3,000 items through a bounded buffer over the condvar with no loss, no duplicates, and zero `[PANIC]`. Making it reliable exposed a real scheduler wake-path bug (see the v38.27 changelog).
- The 3,384-line shell monolith split into a dispatcher + 72 per-command modules; in-kernel GDB stub (COM2, breakpoints, single-step, DWARF symbols).

## Architecture

```
+--------------------------------------------------------------------+
|                       GRUB Multiboot (VBE)                         |
+--------------------------------------------------------------------+
|  boot.asm  -->  kernel.c  (kernel_main entry point)                |
+--------------------------------------------------------------------+
|  GDT (Ring 0+3)  |  IDT (ISR+IRQ)  |  TSS  |  Syscall (int 0x80)   |
+--------------------------------------------------------------------+
|  PIT Timer (1kHz, BSP) |  LAPIC Timer (per AP)  |  PS/2  |  Serial |
+--------------------------------------------------------------------+
|  Memory Manager  |  VMM (per-process page dirs, COW, mmap, shm)    |
+--------------------------------------------------------------------+
|  ACPI (RSDT/XSDT/MADT)  |  SMP (APIC/IOAPIC, 4 cores)              |
+--------------------------------------------------------------------+
|  Per-CPU Runqueues  |  Semaphores & Futexes  |  VFS + ATA PIO + AHCI + xHCI USB + virtio-blk |
+--------------------------------------------------------------------+
|  VGA/VESA Driver   |  Window Manager  |  RTL8139 NIC (IRQ-driven)  |
+--------------------------------------------------------------------+
|  Network Stack (Ethernet/ARP/IPv4/ICMP/UDP/TCP/DNS)                |
+--------------------------------------------------------------------+
|  MCT + ELF32 Loaders |  Ring 3 User Tasks |  GDB Stub (COM2)       |
+--------------------------------------------------------------------+
|  Desktop |  Taskbar  |  Login Screen  |  fd layer  |  UNIX pipes   |
+--------------------------------------------------------------------+
```

## Core Subsystems

### Kernel & Memory

| Subsystem | Highlights |
|---|---|
| Virtual Memory (`vmm.c`) | Frame-bitmap allocator (32 768 pages), per-process page dirs, region allocator, COW with refcounts |
| Demand paging | `mmap()` reserves zero frames; the PF handler lazily maps+zeroes one page per fault |
| Shared memory | System V segments, `PAGE_SHARED` skips COW, leak-proof attach bitmap |
| Syscall layer | Modular handlers, every user pointer validated (`validate_user_ptr`) |
| GDT/IDT/TSS | Ring 0/3 segments, interrupt-gate IRQs, trap-gate `int 0x80` (preemptible syscalls) |
| Debugging | In-kernel GDB stub (RSP on COM2): F12 break, breakpoints, single-step, DWARF symbols |

### Scheduling & SMP (`task.c`, `smp.c`, `apic.c`)

- Per-CPU runqueues with priority (IDLE < LOW < NORMAL < HIGH) + aging; work-stealing migration between cores.
- APs tick via their own LAPIC timer (PIT-calibrated once on the BSP before AP wake — prevents timer storms).
- One `task_lock`, cli-first everywhere; signal delivery on the syscall-return path is locked too.
- Task states: FREE / RUNNING / READY / SLEEP / BLOCKED / STOPPED / ZOMBIE; hlt-park for zero-CPU waits.
- Per-CPU load sampling → `SYS_GET_SYSINFO` (`cpu_count`, `cpu_load[4]`) → SysInfo live bars.
- 16 KB kernel + 64 KB user stacks per task; per-CPU TSS with kernel-stack switching.

### Process Model (`syscall_proc.c`, `loader.c`)

| Feature | Notes |
|---|---|
| `fork()` | COW address-space clone, kernel-stack frame copy from `TSS.esp0 - sizeof(registers_t)` (deterministic), fd/handler/mmap/shm inheritance |
| `exec()` | Live syscall-frame patching; caught handlers reset to default, pending signals cleared (POSIX) |
| `waitpid()` | Blocks in TASK_STATE_BLOCKED, reaps zombie, WNOHANG; 15 s orphan-zombie safety net |
| Signals | sigaction/sa_mask/sigprocmask/SA_RESTART; sigframes on user stack; default action = exit `128+sig` |
| Job control | pgrp/session per task; SIGTTIN/SIGTTOU on background tty access; fg/bg/jobs/kill %n |
| Shell | env vars + `$VAR`, aliases, tab completion, scripts, `ps`/`kill`/`uptime`/`memstat`, `fetch`; POSIX toolkit `uname`/`whoami`/`hostname`/`env`/`seq`/`head` |

### Filesystems & Storage

- **VFS** — 16-slot node table over ATA PIO, auto-save, growth guard (files move to the end of disk instead of overwriting neighbors).
- **ext2** — fully writable secondary partition: block/inode bitmap allocators, file grow/truncate (direct + singly-indirect), directory entry create/remove/rename with slack-splitting, superblock sync; allocators refuse metadata blocks; host `fsck.ext2` clean.
- **FAT32** — third drive (secondary slave, `index=3`), mounted at `/fat32`: BPB parsing, FAT cluster-chain traversal, **long file names (LFN) read + written** (reverse-order chain, checksum-verified; SFN fallback), cluster allocation/free on write/create/delete, whole-tree rebuild at mount; volumes created by host `mkfs.fat`/mtools work both ways.
- **FD layer** — 32 fds/task, 256 global, typed (`FILE`/`PIPE_READ`/`PIPE_WRITE`/`DEV`), refcounted, closed on task teardown.

### Network

- RTL8139 driver (bus mastering, IRQ 11 → INT 43), spinlock-serialized TX/RX (SMP race fix).
- Full in-kernel stack: Ethernet, ARP, IPv4, ICMP, UDP, DNS (via QEMU gateway `10.0.2.3`).
- Multi-connection TCP: 8 slots, per-conn seq/ack + 16 KB RX buffer, retransmit (5×6 s) + connect timeout (10 s), FIN handshake.
- UDP bind/send/recv syscalls; `fetch [domain]`, `ping`, `host` shell commands; host `gateway.py` proxy for real-internet HTTP.

### GUI & Input

- Double-buffered WM: dirty-region tracking, z-order, rounded corners, traffic-light buttons, Aero snap, 8-directional resize (min 220×150), minimized-window ghost prevention.
- Desktop: baked wallpaper, squircle icons, draggable + persistent positions, double-click launch.
- Taskbar: per-app icon buttons, WiFi indicator, CAPS + HDD LEDs, WIB clock; system tray.
- Input: IntelliMouse 4-byte protocol + scroll wheel (event type 4), shared `ps2_drain()` 8042 arbitration, modifier-key tracking (Alt+Tab).
- Rendering: triple-buffer delta compositing (~4 ms/frame), enforced clip rectangle on all primitives.

### Audio

- SB16 native driver, 8/16-bit mono/stereo WAV streaming, tone synthesis, volume control (scroll-adjust), mapped to QEMU's PulseAudio backend.

### App Runtime

- `.mct` binary format (16-byte header, fixed-base mapping) + standard ELF32 ET_EXEC loader (auto-detected by magic).
- Shared-library system (`libc.mct`): dynamic symbol resolution via export-table pointer; app binaries ~2 KB.
- `SYS_SET_STDOUT_IPC` lets apps stream output to queues; pipelines/redirection via `task_fork_exec` + dup2 rewiring.

## Build and Run

### Requirements
`gcc (-m32)` · `nasm` · `make` · `qemu-system-i386` · `python3` + `Pillow` · `grub-mkrescue` + `mtools` · `mkfs.ext2` (for the ext2 drive)

### Commands
```bash
make clean && make        # build kernel + apps + ISO assets
./run.sh                  # KVM boot: 4 cores, gateway proxy, serial -> serial_debug.log
```

`run.sh` boots `mectov.iso` with `-smp 4`, the RTL8139 NIC, SB16 audio, and three drives: `disk.img` (MECTOVFS, index 0), `ext2.img` (index 1) and `fat32.img` (a 16 MB FAT32 volume at index 3 — index 2 is the CD-ROM; created with `mkfs.fat` if missing), streaming the serial log to `serial_debug.log` (also copied to `log.txt`). The Web Gateway Proxy (`scripts/gateway.py`) gives the guest real internet access.

The whole toolchain builds optimized: the kernel and embedded DOOM compile at `-O2 -march=i686 -fno-pie -fno-pic` (no GOT/PIC indirection — the kernel is linked at a fixed 1 MB and never relocates), and every Ring 3 app, `libc.mct` and ELF demo builds at `-O2`.

### Building User Applications
```bash
make apps/hello.mct       # builds any apps/<name>.c -> apps/<name>.mct (baked into the VFS)
```
App binaries are produced by `scripts/build_mct.py` (freestanding, entry `_start`, linked at `0x08000000`) and injected into the VFS by the Makefile. Standard ELF32 binaries work too:
```bash
python3 scripts/build_elf.py apps/elfdemo.c elfdemo.elf
```

### Debugging with GDB
```bash
# Terminal 1 — boot with COM2 as a GDB server
qemu-system-i386 -cdrom mectov.iso -m 128 -smp 4 \
  -serial file:serial.log -serial tcp:127.0.0.1:2345,server=on,wait=off \
  -drive file=disk.img,format=raw,index=0,media=disk

# Terminal 2 — attach (press F12 inside the guest to break in)
# (symbols live in myos.bin.debug since v38.81 — myos.bin itself is stripped)
gdb myos.bin.debug -ex "target remote :2345" -ex "c"
```
