q3dm1 on KVM: 19 fps → 66 fps

320×240 render, 642×502 window (Q3ARENA_SCALE=2), Q3A-default visuals — no resolution was lowered. Deterministic harness: no local QEMU window, so no host mouse path into the guest.

  • Clocks split. The 50 ms server tick no longer paces the frame; ticks catch up at the top of each rendered frame (capped at 125 ms) and the loop's only delay is a 15 ms limiter. In the v38.115 session 11.2 ms of every frame was spent waiting for a clock whose work was already done.
  • Histogram gated. Reading the finished ZBuffer for the pixel line cost 7.4 ms/frame; it now runs on sampled frames only (frame % 20 == 0).
  • Exact frustum cull. 5430 triangles were emitted per frame and ~68 reached the raster: the old “quorum” could never drop a face the PVS kept. A face is now dropped only when all of its own vertices lie behind one of the six planes — emitted faces in the parked view 2415 → 3, GL 15.77 → 6.3 Mcycles/frame, with the fill unchanged (6.06 → 6.03 Mcycles: the same pixels).
  • Verified by pixels. Pre-cull and post-cull runs compared scene by scene at matched game time: 68 scenes, zero pixel mismatches. q3arena, q3vis, q3retail all PASS.
  • Measured and rejected: -O2 for the TinyGL tree (gl 17.4 → 27.1 ms at the same view), and backface culling (the fork's glFrontFace bug is fixed, but wall and patch windings disagree).
